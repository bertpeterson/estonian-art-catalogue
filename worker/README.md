# The mood page's reader (Cloudflare Worker)

`mood.html` / `meeleolu.html` send a visitor's typed description here, and `find.html` / `leia.html`
(build_ask.py) send their conversation to the same Worker at `/ask`: Claude answers with a short
reply and a search (mood words, kind, size, budget), and the page picks the works for sale itself. The Worker asks
Claude Haiku which of the catalogue's 86 mood and subject words fit it, and returns them;
the page ranks the pictures itself. About $0.0012 a search, from the Anthropic Console
credit. Without the Worker the page still works: typed words are matched by stems.

- `template.js`: the Worker, with a placeholder for the vocabulary. Edit this one.
- `mood-worker.js`: generated by `build_mood.py` with the vocabulary written in. This is
  the file to paste into Cloudflare. When the build says it changed, paste it again.

## Setting it up (once)

1. **A key of its own.** In the Anthropic Console, API keys → Create key, name it
   `museaal-mood`. Under Limits, a monthly spend limit (e.g. $10) caps what the page can
   ever cost. Keep the key window open for step 4.
2. **A Cloudflare account.** dash.cloudflare.com → Sign up (free plan). The domain stays
   where it is; nothing moves.
3. **The Worker.** Workers & Pages → Create → Create Worker → name it `museaal-mood` →
   Deploy. Then Edit code: select all, paste the whole of `mood-worker.js`, Deploy.
4. **The key.** The Worker's Settings → Variables and Secrets → Add → type Secret, name
   `ANTHROPIC_API_KEY`, value: the key from step 1 → Deploy.
5. **The address.** The Worker's page shows it, like
   `https://museaal-mood.<your-name>.workers.dev`. It goes into `data/mood_api.json`
   (`{"url": "https://museaal-mood.<your-name>.workers.dev"}`); the next build puts it in
   the page and in the Content-Security-Policy.

## Turnstile (bots kept off the Anthropic key)

The Origin check stops other sites' pages, not a script, which can send any Origin it likes. Cloudflare
Turnstile closes that: the page runs Cloudflare's check as it opens (unseen unless Cloudflare wants a click)
and sends the token with the first message; the Worker checks it with Cloudflare and answers with a pass
for 30 minutes (an HMAC of the visitor's address and the expiry), which the page sends from then on.

1. dash.cloudflare.com → Turnstile → Add widget: hostname `museaal.ee`, mode Managed. It gives a site key
   and a secret key.
2. The Worker's Settings → Variables and Secrets → Add → Secret `TURNSTILE_SECRET`, the secret key → Deploy.
3. The site key into `data/mood_api.json` as `"turnstile": "0x…"`, and push: the build puts it in the
   pages and lets `challenges.cloudflare.com` into their Content-Security-Policy.

Order does not matter much: without the secret the Worker lets everyone through as before; with the secret
but before the pages carry the key, the mood box falls back to stems and Buy Art's assistant says "Please
confirm you are not a robot" until the push is live. Of `/list/*` only `/list/login` is behind it, since each
sign-in link is an email sent; the rest spends nothing.

## Limits built in

Answers museaal.ee only (the browser's Origin header); 20 searches a minute per visitor;
200 characters; the answer can only be words from the vocabulary (a JSON schema with
the words as an enum), so no text a visitor types comes back to the page. The sentence
is not stored.

`/ask` (Find a work): the last twelve turns, 400 characters a visitor message; Claude's reply
is capped at 600 characters and shown as plain text, never as HTML; the search fields are
checked against the vocabulary and the allowed values. Each message is one call: Haiku for
English (about $0.002), Sonnet 5.5 for Estonian, where Haiku's Estonian was clumsy (about $0.004,
thinking off, with Anthropic's server-side fallback for a mistaken safety decline). The Worker,
not the model, picks the reply's language. Same key and monthly spend limit. Nothing is stored.

With `tools: 1` (find.html sends it) Claude may first call search, artist and similar, in up to two
rounds a message. The page runs them on its own stock.json and posts the conversation again with the
results; the Worker passes Claude's turns back unchanged and accepts picks only from works the results
named. Each round is a call, so a message costs a few times more. 20 messages and 60 requests a minute
per visitor.

A photo (Find a work's "Photo of your wall"): the page shrinks it to 1280 px and re-encodes it, which
drops its location data, and sends it with the message. Sonnet 5.5 marks up to three empty wall areas,
an object of known size (a door is 80 cm) and two level lines along the wall; the Worker turns those
into centimetres and the wall's perspective itself (the model places things well and measures badly).
6 photos a minute per visitor, about $0.007 a photo. The photo is not stored.

## My List across devices (`/list/*`)

A visitor types their email address under My List; the Worker emails them a sign-in link, and the list is then
kept in step on every device they open the link on (`list-sync.js`, which `list_sync.py` puts in the pages).
In KV the keys are hashes: the list under an HMAC of the address, sessions and links under their SHA-256. The
list's record also keeps the account's address (the sign-in text says so), and the key's metadata repeats it with
the day the account began, for the backoffice. Accounts from before 15 Oct 2026 kept no address; they get it at
their next sign-in. 1,000 works a list at most; a list not changed for two years, and a session after one, expire.
"Delete account" deletes the stored list and its address. The address is used for sign-in links only, and for
news only with the `n:` opt-in below.

**News emails.** The sign-in has an unticked "Email me about new features" box. Only for those who tick it and
then open the link (so the address is confirmed) does the Worker keep `n:<account>` in KV: `{e, lang, at, v,
unsub}`, the address, their language, when they confirmed, the wording version, and their own unsubscribe link.
It stays until they use that link, press "Stop them" signed in, or delete the account. To read the list:
Cloudflare → Storage & Databases → KV → `museaal-lists` → search keys for `n:`, or in Terminal
`npx wrangler kv key list --namespace-id <id> --prefix n:` and `npx wrangler kv key get --namespace-id <id> "n:…"`.
Every news email must carry that person's `unsub` link (in the text, and as the `List-Unsubscribe` header).
The page promised this when they ticked the box, so nothing else may be sent to these addresses.

Setting it up (once), in this order:

1. **Resend** (resend.com, free plan: 3,000 emails a month, 100 a day). Sign up, Domains → Add domain →
   `museaal.ee`, region EU. It lists DNS records (a DKIM TXT on `resend._domainkey`, an MX and an SPF TXT on
   `send`): add them at Veebimajutus exactly as shown. They sit beside ImprovMX's records and change nothing
   for info@museaal.ee. Wait for "Verified". Then API Keys → Create, permission "Sending access", domain
   museaal.ee.
2. **The store.** Cloudflare → Storage & Databases → KV → Create → name `museaal-lists`. Then the Worker's
   Settings → Bindings → Add → KV namespace, variable name `LISTS`, namespace `museaal-lists`.
3. **Two secrets** (Settings → Variables and Secrets → Add, type Secret): `RESEND_API_KEY`, the key from step 1;
   `LIST_SECRET`, a long random string (`openssl rand -base64 32` in Terminal). Never change `LIST_SECRET`
   afterwards: every account is made from it, and a new one strands them all.
4. **Re-paste** `mood-worker.js` and Deploy.
5. **Switch it on in the site:** `"lists": true` in `data/mood_api.json`, build, push. Until then the pages carry
   no sign-in (a local build can with `MUSEAAL_LISTS=1`).

Optional: `MAIL_FROM` (plain variable), default `museaal.ee <list@museaal.ee>`. Replies go to info@museaal.ee.

Limits: 5 sign-in requests per visitor per ten minutes, 4 links per address per hour, 30 list requests a
minute. KV's free plan allows 1,000 writes a day: a sign-in is about four, a change to a list one.

## The backoffice (`/admin/stats`, page museaal.ee/admin)

`site/admin.html` (build_admin.py) is not linked anywhere and is noindex. It asks once for a key and keeps it in
that browser. With the key the Worker returns the KV's keys counted by kind (`u:` accounts, `n:` news opt-ins,
`s:` signed-in devices, `t:` waiting links), every account's address with the day it began, its day counters for 30 days (`c:signup:`, `c:ask:`, `c:mood:`
followed by the date, kept 400 days), and GoatCounter's visits, pages, referrers and events. The page itself adds
stock by gallery (from the build) and each workflow's last run (from GitHub's public API).

Setting it up (once):

1. **ADMIN_KEY.** Make a long random key (in Terminal: `openssl rand -base64 24`), keep it in your password manager,
   and add it to the Worker under Settings → Variables and Secrets as a secret named `ADMIN_KEY`.
2. **GOATCOUNTER_TOKEN** (for the visits). GoatCounter → Settings (your user menu) → API → New API key, with only
   "Read statistics" ticked. Add it to the Worker as a secret named `GOATCOUNTER_TOKEN`.
3. Paste `mood-worker.js` into the Worker again and deploy, then open museaal.ee/admin and enter the key.

The day counters start when the new Worker goes live: nothing before that is known. Each question and each mood
reading is one KV write; the free plan allows 1,000 writes a day across all keys, and a failed count never stops
the answer. Wrong keys: five a minute per visitor.
